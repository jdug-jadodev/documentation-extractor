# Ubicación de un desarrollo y criticidad

Reemplazar `[DESCRIBIR AQUÍ EL DESARROLLO]` antes de enviarlo.

```text
Usa el último run de los tres repositorios.
No reanalices y no modifiques código.

Necesito decidir dónde implementar este desarrollo:

[DESCRIBIR AQUÍ EL DESARROLLO]

Analiza el conocimiento extraído y prepara una recomendación que incluya:

- repositorio recomendado;
- módulo o capa donde podría ubicarse;
- responsabilidades existentes relacionadas;
- alternativas consideradas;
- contratos HTTP afectados;
- datos afectados;
- consumidores y dependencias;
- compatibilidad;
- pruebas necesarias;
- riesgos;
- impacto transversal;
- rollback;
- decisiones pendientes.

Cataloga la criticidad propuesta como baja, media, alta o crítica,
explicando por separado:

- impacto de negocio conocido;
- exposición externa;
- sensibilidad de datos;
- cantidad de componentes afectados;
- cambios de contrato;
- complejidad de rollback;
- relaciones candidate o unresolved;
- calidad y cobertura de la evidencia.

La criticidad es una evaluación propuesta, no la clasificación
oficial de la empresa.

Si falta dominio, propietario, SLA o clasificación empresarial,
marca “Configuración empresarial pendiente”. No lo inventes.

Genera un ADR como borrador en Obsidian.
```
